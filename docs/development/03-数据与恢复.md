# 数据、统计与恢复合同 v0.2

## 1. 保存位置与基本原则

- 用户数据放在当前Windows用户的 `%LOCALAPPDATA%\HealthyWorkClock\`，不要写程序安装目录。
- 第一版数据库 `healthy-work.db`；日志在 `logs/`；数据不联网。用户可以另选导出目录。
- 所有时长均为64位整数毫秒；时间戳为UTC，另保存当时的时区与本地日期口径。
- ID采用UUID文本或等价唯一类型；读写参数化；开启外键约束；结构迁移有版本和事务。
- 初版不做静默自动备份，以免“清空记录”后仍留下隐藏的私人备注副本。数据库迁移如需备份，必须记录路径和保留策略，清空/隐私说明同步更新。
- 本地保存不等于数据库加密；初版不承诺加密防护。日志不得包含接续事项、完整SQL参数、其他软件内容或屏幕信息。

## 2. 数据结构

v1.11.0 增加可选的 `SettingsSnapshot.Arrangement` JSON 属性，保存有序计划、组合定义及按 ID 复用的引用，与计时执行方案一起保存。旧数据缺该属性时，打开设置会从旧方案为每个已有组合生成独立定义，保持编排和动作。保存后保留这些 ID。活动轮的检查点继续保存启动时的执行方案。

v1.12.0 读取 v1.11.0 的组合库时，为旧定义按原顺序分配名称编号，将旧 `Count` 移到所有对应引用的 `RepeatCount`，含组合内部的引用。迁移保留定义 ID、执行方案和已保存的轮序。再次保存设置时写出新字段。只存在库中的空组合允许持久化。

v1.10.0 的有序模块树和休息合并开关作为可选属性保存在现有 JSON 计划中。旧版固定计划和层级计划可直接读取。恢复合并休息时，用已保存的实际休息时间定位原动作并算出整个合并段的剩余时间。首尾相接时，轮序记住首次开场休息是否已经执行。工作模块即便没有接续休息也独立写入历史。

v1.9.0 为现有设置与检查点增加可选的循环信息。设置存储已完成轮数和方案代次。检查点保存本轮启动时的方案、所在轮序、代次、已休息总毫秒数及当前提示。重新启动后保持暂停，由已休息时长定位段落。完成轮次与推进循环在同一事务内提交。一个计划生效前已开始的旧轮可以正常计入统计，其完成不会推进新计划。早期记录缺少循环信息时按固定时长读取。整轮只生成一个轮次记录，连续休息段的实际时间累加，每项活动仍需自报。

v1.17.16 在计划中保存工作合并标志，用于区分新版计划与旧版以独立工作模块编号的检查点。旧计划开启连续休息合并时，在安全的循环边界启用工作合并。正在执行的旧圈按旧序恢复和完成，新计划和进度按原事务规则保存。

### `settings`：下一轮的默认设置，单行

| 字段 | 类型 | 规则 |
| --- | --- | --- |
| id | 固定1 | 单行 |
| work_duration_ms | int64 | 60,000–10,800,000，整数分钟 |
| rest_duration_ms | int64 | 60,000–1,800,000，整数分钟 |
| ReminderRates | 六个有限浮点数 | 按眼睛、肩颈、腰背、腹部、臀腿、肛门依次默认 12、10、8、3、9、2 分／小时，分别接受 0–40。旧数据库缺该属性时使用默认值 |
| notice_duration_ms | int64 | v0.2固定30,000 |
| updated_at_utc | UTC | 修改时刻 |
| schema_version | int | 结构版本，不当作用户设置版本 |

开机自启动默认关闭。在设置页开启时，应用为当前 Windows 用户在 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 中写入 `SandUp` 项，指向当前程序绝对路径并传入 `--startup`。关闭时只删除该项。更改立即写入 Windows，独立于工作计划保存。Windows 登录时通过托盘启动，主窗口由用户打开，计时由用户主动开始。

### `workspace_draft`：当前接续事项，单行

`id=1`、`text`、`updated_at_utc`。最多200个用户可见字符，与界面同一验证函数。新轮继承草稿，历史轮次的备注是独立快照，不依赖这一行永远保留。

### `sessions`：一轮一条

| 字段 | 含义 |
| --- | --- |
| session_id | 主键；窗口数量不会增加会话数量 |
| started_at_utc / ended_at_utc? | 开始与结束；Active时结束为空 |
| start_time_zone_id / started_local_date | 开始时Windows时区ID与本地日期，供展示与审计 |
| end_time_zone_id? / ended_local_date? | 结束结果按哪一天计数 |
| planned_work_ms / planned_rest_ms / notice_ms | 开始时参数快照，不随settings变更 |
| delay_used | 0或1 |
| requested_delay_ms | 0、180000或300000；用户选择的时长 |
| actual_delay_ms | 实际处于Delaying的时长；预告延后时尚余的原定工作不计入此字段 |
| work_ms / rest_ms | 所有关联片段的聚合缓存；事务维护，与片段求和必须一致 |
| outcome | Active / Completed / Skipped / EndedEarly / Interrupted |
| end_reason? | RestTargetReached / Emergency / UserEndedPaused；后续扩展须迁移/兼容 |
| checkin_status | Unrecorded / Reported；Reported必须至少一个活动 |
| resume_note | 本轮最后成功保存的接续事项快照 |
| updated_at_utc | 最后成功修改时刻 |

`Active`包括暂停中的轮次；系统锁屏、睡眠、正常应用退出不是自动完成，也不自动结束会话。`Interrupted`由用户主动结束暂停中的轮次产生。应急结束结果按 R-05 区分 Skipped / EndedEarly。

### `time_slices`：可信计时片段

| 字段 | 含义 |
| --- | --- |
| slice_id | 主键；同一运行片段的检查点更新此ID，不重复插入全部累计值 |
| session_id | 外键 |
| sequence_no | 会话内稳定顺序，与session_id联合唯一 |
| kind | Work / Rest |
| work_subtype? | Base / Extension / Memo；Rest 为空 |
| started_at_utc / ended_at_utc | 基于可信锚点映射的起止，用于显示；累计以duration_ms为准 |
| local_date / time_zone_id | 片段归属的当时本地日期和时区 |
| duration_ms | 非负；不跨本地午夜，不包含暂停、遮罩创建等待和未知时间缺口 |
| finalized | 是否封口；封口后只允许修复工具修改，业务不得重新增长 |

工作阶段转换为PreBreak不必切开Base片段。预告后延后时，超过原工作目标的部分才属于Extension；例如24:40点延后，接下来的20秒仍是Base。`actual_delay_ms = Extension片段之和`。2026-11-12起休息中不再允许延后；旧版本已保存的Extension片段按原值保留，不改写历史。

跨本地午夜时切片，两个片段时长相加仍等于原单调计时差。时间/时区发生不连续变化则按 R-03 暂停，不能用修改后的系统时钟相减制造负数或多算小时。

### `session_activities`：活动自报

`session_id`、`activity_id`联合主键；`reported_at_utc`。目录ID为 `look_away`、`walk`、`relax_shoulders_hands`、`other`。`other`首版不附加自由文本。

活动是用户自报，不保存“检测完成”。未填写不是“没做”，因此不引入把空值强行转换成失败的字段。

### `runtime_checkpoint`：恢复一个未结束轮次

单行：当前 `session_id?`、`saved_phase`、`resume_phase?`、`pause_reason?`、阶段累计、当前工作目标、延后名额、当前片段ID、当前提示ID、待确认会话ID?、`saved_at_utc`、`storage_revision`。

不存可跨进程继续使用的单调时钟起点。新进程读取后，Working、PreBreak、Delaying、BreakPending、Resting、AwaitingRestMemo、EditingRestMemo 一律转 Paused。待休息、休息和备忘录编辑的恢复目标统一为 Resting。恢复时显示已确认的备忘录。AwaitingCheckIn 仅显示可补记录。

### `operation_receipts`：防重复提交

`operation_id`主键、`command_id?`、`session_id?`、`committed_revision`、最小结果引用。提交成功后重试同一操作返回已提交，不能重复加时长或创建会话。

这是小型去重表，不是完整事件溯源系统。删除已结束轮次时一并清理其回执；已经失效的会话ID/代际不能再被旧命令创建或复活。

## 3. 保存时机和失败语义

| 事件 | 保存要求 |
| --- | --- |
| 新轮开始、暂停、恢复、延后、休息完成、主动结束、活动提交、设置修改 | 事务立即提交 |
| 活动计时进行中 | 最多每5秒写一次检查点，并在阶段切换时封口 |
| 工作备忘录 | 预警点「开始休息」或全屏点「确定」时，与阶段检查点原子保存。预警到点后的持续编辑和全屏内编辑时间按 Memo 子类计入工作 |
| 应急退出 | 立即关遮罩；随后提交，不因写入失败阻止退出 |
| 锁屏/睡眠/正常退出 | 先冻结计时并关遮罩，再尽力保存；事件不能被磁盘等待阻塞 |

数据库健康且进程正常获得调度时，崩溃最多丢失最后一个检查点后的约5秒计时；草稿只有显示“已保存”的部分才保证已提交。磁盘故障、断电和系统强制终止不能承诺绝对不丢失，界面和说明不能写“永久零丢失”。

SQLite事务至少覆盖本次时间片、会话聚合、结束结果、恢复检查点和对应回执。正常休息完成保留窗口，保存成功后显示全屏确认。写入失败则立即关窗，保留内存中的Completed结果和待保存数据，回主窗口处理。

区分两类版本：界面逻辑版本用于拒绝过期按钮；持久化版本用于事务乐观并发。同一应用只有一个写入队列，检查点和用户提交必须有序。

## 4. 统计口径

桌面展示偏好单独保存于同一用户数据目录desktop.json，仅含悬浮沙漏显示开关与窗口位置；不保存或计算另一份计时。首次默认显示，可从设置页及托盘控制；文件缺失或损坏回退默认值。旧数据库的默认NoticeDurationMs在应用载入时统一为20秒并用于新轮，当前未结束轮次参数按记录恢复，领域层兼容旧30秒记录。历史计时数据不重写。

| 指标 | 算法 | 禁止的解释 |
| --- | --- | --- |
| 某日工作计时 | `local_date=该日`的Work片段duration_ms求和，含当前未结束轮次的已提交部分 | 不代表有效劳动时长 |
| 某日休息屏计时 | 同日Rest片段求和 | 不代表用户真实离屏或运动时长 |
| 主页面今天已工作/已休息 | 当日本地日期的已提交Work/Rest片段求和，每5秒重新查询；包含活动轮次已保存部分，跨日按片段日期归属 | 不将内存累计再加到数据库累计，避免重复；有检查点及刷新延迟 |
| 计时完成次数 | `ended_local_date=该日 AND outcome=Completed` | 不取决于是否勾选活动 |
| 每轮平均工作/休息 | 分别取在所选日期结束、对应阶段计时大于0的轮次，求实际时长总和除以轮次数。跨午夜的整轮按结束日归属 | 不使用默认时长，不将零时长算入平均 |
| 跳过/提前结束/中断次数 | 按结束日分别计算三个outcome | 不加惩罚分，不偷偷换算健康评分 |
| 活动自报次数 | 结束日内包含该activity_id的已结束轮次，每轮每类最多1次 | 不能据此估算消耗或治疗效果 |
| 今日耐久度 | 每个本地日六项均从 100 开始。按 UTC 时间重放该日已保存工作片段与结束于当日的自报活动，同刻先处理工作。每段扣分 = 工作毫秒数 ÷ 3,600,000 × 该项基础速度 × [1 + (100 − 该项历史分) ÷ 200]，每次事件后限制在 0–100 | 游戏化休息提醒 |
| 历史耐久度 | 以 100 为初始历史。每个本地有效日结束时逐项结算，新历史 = 0.8 × 原历史 + 0.2 × 该日实际日末分（日内已含原历史的放大效果与已确认活动）。该新历史用于下一天。有效日有正时长工作或休息片段，或有可映射的自报活动。缺失日跳过，无样本时显示“—”并按 1 倍扣分 | 累计全部记录日，历史及今日使用当前设置重算 |

远眺给眼睛加 12，放松肩手给肩颈加 12，走动给腰背、腹部、臀腿、肛门依次加 6、3、12、4。每轮每个自报项目加一次，“其他活动”只计活动次数。历史补填用轮次结束日和时间重算，受影响的后续记录日重新累计。工作跨日按已有时间片归属。报表在同一事务内读取设置、原始计时与自报记录。回看请求日期之前的数据只用于耐久度，普通统计和导出的范围按请求日期。

v1.7.0 的数据库增加变更序号表、受影响日期表和日期索引，用于复用内存中的已结算记录日。普通计时保存只重算发生变化的日期及其后续。删除源记录时清除日期标记，旧缓存从原始记录重建。设置、计时和活动写入与缓存失效标记处于同一 SQLite 事务。重启后从已有明细重建，不要求在零点运行定时任务或写入一条新的健康记录。

历史页从数据库查询，数据最多延迟一个5秒检查点，并显示必要的更新时间。不要再把实时内存的整轮累计加到已提交累计上，造成双算。

跨午夜示例：23:50至00:10连续工作，前日10分钟、次日10分钟。完成次数只计在结束日。系统时区后来改变时，旧记录的归属日不追溯改写。

## 5. 清空与导出

清空必须先让用户看到范围并确认，默认清除所有已结束轮次及其片段、自报和备注；当前未结束轮次及其检查点保留，设置保留。接续草稿默认保留，勾选“同时清空当前接续事项”才删除。

清空事务前协调器阻止新旧写入竞争并排空待提交操作；完成后刷新统计、待确认引用和缓存。若当前正在确认的已完成轮次被清除，回Idle。失败时全不删，不能出现“历史删了但统计还在”。

导出固定包含两份CSV，放进用户指定的新目录：`sessions.csv`与`time-slices.csv`。目标目录已存在且非空时返回明确错误，不能覆盖其中的用户文件。

`sessions.csv`列顺序：session_id、started_at_utc、ended_at_utc、start_time_zone_id、ended_local_date、planned_work_ms、planned_rest_ms、work_ms、rest_ms、requested_delay_ms、actual_delay_ms、outcome、end_reason、checkin_status、activity_ids；仅在用户勾选时末尾增加resume_note。活动ID用分号分隔。

`time-slices.csv`列顺序：slice_id、session_id、sequence_no、kind、work_subtype、local_date、time_zone_id、started_at_utc、ended_at_utc、duration_ms。按日导出以时间片的local_date筛选，并附带所有关联会话及结束日在范围内的无片段会话；会话聚合字段仍表示整轮，跨范围核对每日时长必须使用片段文件。

导出为一致的数据快照：导出中若计时继续，两份文件仍以开始导出时的同一已提交快照为准；在临时目录全部写完后才交付最终目录，取消或失败不报告成功。用户主动勾选后才包含接续备注，并对以公式符号开头的文本作电子表格公式防护。不得删除或覆盖用户未选择的文件。已导出的用户文件不随应用内清空自动删除。

## 6. 恢复验收要点

1. 任何活动阶段强制结束进程后启动，都不会立即全屏、自动继续或补算离线时长。
2. 最后一次成功提交后的计时可恢复；延后名额、已休息时长和接续文字保持一致。
3. 保存失败时应急关闭仍成功；重试成功只得到一份记录，时间片不会重复。
4. 损坏库展示明确错误并保留原文件，不用空库伪装恢复成功。
5. 完成结果和待确认页之间崩溃后，结果仍只存在一次；活动状态仍是Unrecorded。
6. 结构升级失败回滚，旧库可识别；旧版本程序遇到更高结构版本应停止写入并提示，不尝试降级覆盖。
