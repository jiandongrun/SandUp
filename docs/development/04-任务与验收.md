# 分批任务与验收标准 v0.2

## 1. 总原则

交付按M0到M5顺序推进。一批可由同一个AI持续完成，也可换AI；换人时必须提供完整仓库、合同和上一批交付报告。不要让几个不了解彼此修改的AI同时改共享接口。

验收分三层：纯规则测试证明算得对；数据库测试证明存得对；Windows实机证明窗口、睡眠和退出能工作。三者不能互相代替。

## 2. 每批任务单

### M0：能构建的工程骨架与合同类型

- 输入：本目录全部文档、现有草图；从空仓库也能执行。
- 范围：建立 `02` 指定的项目和依赖方向；固定.NET 10稳定SDK、依赖和测试框架；定义公共DTO、枚举、接口与注入入口。
- 交付：可构建的解决方案；启动后仅显示明确标注的空壳主窗；测试可运行；开发README含构建、测试、启动命令；依赖清单与锁定文件。
- 验收：干净环境按README可还原依赖并构建；Domain不引用WPF、SQLite；没有联网业务和虚构完成数据。
- 不做：实际计时、多屏遮罩、统计美化、云功能。接口占位必须标明未实现，不能返回成功冒充可用。
- 退出条件：合同类型与 `02/03` 对齐，构建证据齐全。不能以“已经生成文件”代替构建。

### M1：可独立验证的计时核心

- 输入：M0骨架及规则R-01～R-08。
- 范围：SessionEngine、状态转换、假时钟、命令串行协调的基础；先接假窗口/假存储。
- 交付：计时核心与领域测试；每个测试标注T编号；状态轨迹输出能说明每段时间归属。
- 验收：T01～T13、T19、T20、T22、T29、T30中的纯逻辑部分通过。
- 不做：为了让测试通过而放宽合同；在界面中再写一套倒计时；等待真实25分钟运行测试。
- 退出条件：有效时间、延后次数、跨阶段结算和重复命令可确定地复现。

### M2：本地数据、事务、恢复与查询

- 输入：M1稳定合同；数据库字段表。
- 范围：SQLite结构与迁移、事务、检查点、去重、草稿保存、查询统计、CSV导出和历史清空。
- 交付：建库/升级机制；临时数据库集成测试；恢复报告；导出示例；没有个人内容的故障日志样例。
- 验收：T14～T18、T21、T23～T26、T28、T32、T33的数据部分通过。
- 不做：静默清空坏库、把明文库声称为加密、把保存失败显示成成功。
- 退出条件：写入故障和进程恢复测试可重复，统计可由原始时间片重新算出同样结果。

### M3：Windows外壳与窗口安全退出

- 输入：M1/M2；可用的Windows环境。
- 范围：WPF主窗、托盘、单实例、所有显示器休息窗、系统事件适配、窗口批次与关闭通道；界面先简洁。
- 交付：可以真实呈现和关闭的Windows程序；主窗/托盘/双屏录屏；系统事件诊断记录；已验证与未验证的环境列表。
- 验收：T08～T13、T19、T22、T27、T31中的Windows部分通过；任何显示失败都能退回桌面。
- 不做：键盘钩子、屏蔽系统快捷键、要求管理员权限、系统锁屏或强制锁机。
- 退出条件：先证明用户不会被困在遮罩中，再进入界面精修。没有双屏设备就列为未验证，不填写“通过”。

### M4：五个界面与完整用户流程

- 输入：已验证的核心、存储和Windows窗口；五张草图。
- 范围：工作页、预告、休息屏、确认页、今日历史；另补必要的暂停/存储错误/空记录/设置状态。
- 交付：可从开始走到记录的完整版本；文字和按钮映射表；所有页面的截图；一次正常流程与一次应急流程录屏。
- 验收：所有按钮调用统一应用命令；活动默认未选；旧记录可补填；修改设置不重置本轮；草稿保存状态真实；键盘操作可用。
- 不做：把HTML草图直接装进网页壳当作原生实现；以硬编码数字和假历史替代实际计时。
- 退出条件：T01～T33所有已实现相关路径可操作；视觉草图允许合理调整，但规则不能悄悄改变。

### M5：实机验收与可交付运行包

- 输入：M4、完整用例表和发布目标。
- 范围：干净环境构建、性能测量、连续运行、打包、用户说明、依赖许可清单、已知问题清单。
- 交付：Release自包含Windows x64运行包、源码、构建说明、测试报告、验收矩阵、用户使用说明、数据位置/导出/卸载说明。
- 验收：T01～T35均有状态和证据；所有核心正确性/退出/数据损坏问题解决；未支持的设备和场景明确写出。
- 发布信息：文件签名状态如实说明；不声称未签名产物已受系统信任，不要求用户关闭系统安全防护。签名证书采购和商店发布不属于本批自动执行范围。
- 退出条件：用户拿到包可按说明运行；“构建成功”不能代替运行成功；“某台电脑运行”不能代替兼容性结论。

## 3. 可执行验收用例

测试默认工作 25 分钟、休息 5 分钟、提前 20 秒挥手和 10 秒弹窗。除缺口测试外，假时钟按不超过正常节拍间隔推进，避免绕过时间缺口规则。窗口成功反馈和保存反馈都要可控制。

| ID | 操作 / 条件 | 必须观察到的结果 |
| --- | --- | --- |
| T01 | 开始，推进24:40、再20秒、呈现成功、再休息5分钟 | Working→PreBreak→BreakPending→Resting→AwaitingCheckIn。工作25、休息5，一条Completed，活动Unrecorded。原全屏窗显示“休息完成”，等待期间时长不增加 |
| T02 | 24:40在预告选择延后3分钟 | 剩余3:20；28:00进入待显示；工作28分钟，Extension3分钟；不再次进入PreBreak，但结束前仍20秒挥手、10秒弹窗且无延后按钮 |
| T03 | 24:40延后5分钟，28:00点击现在休息 | 工作28分钟，RequestedDelay5分钟但ActualDelay3分钟；不是30分钟 |
| T04 | 工作25、休息2，尝试延后3或5分钟，再休息3 | 休息屏无延后按钮；命令拒绝且不关闭窗口；总工作25、总休息5、一次Completed |
| T05 | 任意延后已使用，再暂停/恢复/重启，尝试延后 | DelayAlreadyUsed；名额仍为1，不能再延后 |
| T06 | 工作10分钟点击现在休息，完成5分钟休息 | 工作10、休息5；不补成25；正常Completed |
| T07 | 工作10分钟暂停20分钟，再继续5分钟 | 工作15、剩余10；暂停的20分钟不计入 |
| T08 | 预告、延后、待呈现、休息分别应急退出 | 当前窗口全部关闭、回Idle、不再重弹；未休息为Skipped，有有效休息为EndedEarly |
| T09 | 休息窗口或全屏确认按Esc、Alt+F4或点击关闭 | 立即关全部窗口，下一轮手动开始。确认阶段保留已有Completed结果 |
| T10 | 工作10分钟锁屏1小时，再解锁 | Paused，工作10；无自动继续或补算；手动继续后恢复剩余15 |
| T11 | 休息2分钟后睡眠1小时，唤醒并手动继续 | 唤醒不遮屏；重建窗口成功后休息剩余3分钟 |
| T12 | 真实双屏；第二屏创建失败或超时2秒 | 第一屏也回收；Paused；休息不计时；可看到非阻挡错误 |
| T13 | 休息中拔掉副屏/改变缩放 | 重新枚举，关闭旧批次；创建等待不计时；成功后继续；失败退回Paused |
| T14 | 写完检查点，增加不足5秒后强制杀进程 | 恢复为Paused，保留最后成功检查点；不补算离线时间；无自动遮屏 |
| T15 | 休息完成已落盘、填写前杀进程 | Completed只有一条；活动仍Unrecorded；启动可补记录，不自动工作 |
| T16 | 应急退出时注入磁盘写失败 | 先关闭所有窗口；显示记录待保存；恢复写入后重试得到唯一结果 |
| T17 | 同一CommandId提交两次、保存成功回执丢失后重试 | 只生成一个会话/一个结果；不双算时间、不重复开始 |
| T18 | 结束阶段写事务中途失败 | 会话、片段、检查点全成或全败；恢复后不存在半个完成状态 |
| T19 | 工作时将系统时钟向前/后改1小时 | 暂停并提示；无负数和凭空增加1小时；手动恢复建立新锚点 |
| T20 | 假时钟在两个节拍间跳过10分钟且无系统事件 | TimingGap暂停到最后可信节拍，未知间隔不计时 |
| T21 | 23:50至次日00:10工作 | 两日各10分钟；累计20；结束结果按结束日计数 |
| T22 | 主窗口关闭、第二次启动、托盘退出 | 关闭留托盘并继续；第二实例不新建计时；退出后无残留遮罩或进程 |
| T23 | 当前工作进行中修改为40/8 | 本轮计划和剩余不变；下一轮使用40/8；重启也不改变当前轮快照 |
| T24 | 休息完成，空选继续；另一轮勾选走动并保存 | 两轮都Completed；第一轮Unrecorded，第二轮Reported，活动计数只增1 |
| T25 | 分别忽略预警备忘录、选中后等到 00:00、在全屏选中并再确认 | 忽略时直接全屏；预警到点后留在原弹窗；全屏编辑冻结休息并计工作，同一窗口确认后续计；两处确认保存文字，超限保留可编辑文本 |
| T26 | 清空已结束记录时仍有活动轮次 | 二次确认；已结束记录/统计/活动一起清；当前轮、设置、未选删除的草稿保留；旧异步回调不能复活记录 |
| T27 | 结束休息与应急点击同时入队；旧ShowAsync之后才成功 | 只有一份最终结果；所有旧批次关闭；不会因晚到回调再次全屏 |
| T28 | 数据库损坏、迁移失败或高版本库由旧程序打开 | 保留原库，明确报错，禁止写入；不能静默建空库并声称恢复 |
| T29 | 休息屏显示等待1.5秒后成功 | 等待1.5秒既不算工作也不算休息；成功后开始完整剩余休息 |
| T30 | 延后到期前暂停，恢复后提前结束延后 | 仅累计实际工作；原延后名额和已经休息时长保留 |
| T31 | 远程会话断开/重连、Windows锁屏/睡眠/注销分别测试 | 活动计时冻结、遮罩关闭；恢复不会自动继续；记录具体系统与设备条件 |
| T32 | 边计时边查询和导出；CSV含逗号/换行/公式开头文本 | 导出快照一致，正确转义，无公式执行文本；取消不留伪成功文件；默认不导出备注 |
| T33 | 同一时间片多次检查点，累计到1分钟 | 所有片段之和=会话聚合=60秒；不是5+10+15…秒叠加 |
| T34 | 网络断开、普通用户权限、全新用户目录启动 | 核心流程全部可用；无账号/外网素材依赖；不索要管理员权限 |
| T35 | 连续运行与资源测试 | 满足下列暂定指标或给出实测差距；无逐轮窗口/订阅/句柄泄漏 |
| T36 | 首次工作 30 分钟，查看主页，再自报远眺或走动 | 默认六项依次为 94、95、96、98.5、95.5、99。每项有图标、今日与历史连续条。无历史显示“—”。全屏勾选只预览对应部位，确认后更新 |
| T37 | 分别查询单日与跨日范围，含空日、跨午夜片段与历史补填 | 昨日结束前历史 90、实际日末 70 分，今日同项历史 86 分。八天或更久之前的有效日仍有权重。缺日跳过，补填后按日期级联。普通时长、活动次数与 CSV 维持原日期归属 |
| T38 | 设置中编辑、恢复默认、保存，再打开；检查窄窗口和全屏 | 各项支持 0–40、小数及关闭扣分。无效值禁止整组保存。恢复默认待保存生效，旧记录可重算。窄窗可见两列，低分辨率全屏可滚动和应急退出 |
| T39 | 在本地午夜前后读取同一轮次，分别模拟窗口停留、异步读跨日和隔日重启 | 午夜结算历史，新日六项从 100 分起，午夜后的工作计入新日。延迟返回的旧日读数不能覆盖新日，已有记录可重复回算且不会重复结算 |
| T40 | 依次指向六个部位的图标与名称，将指针移入卡片并交替使用键盘焦点和鼠标 | 依次显示“休息方式”“久坐伏案”“依据”。卡片可停留阅读，Esc 或切页即收起。查看资料不改变耐久度或计时 |
| T41 | 添加两层组合，在组合内外放入工作与休息，切换「合并连续模块」 | 右侧竖排展开最外层循环。开启后，相邻工作合成一段，连续休息显示总倒计时并按原时间点切换动作。关闭后按原模块显示 |
| T42 | 中途退出、暂停、在外层休息中重启，或在当前轮进行中改计划 | 进度随完成结果原子提交。未完成保留轮序，恢复可续计对应段。当前轮保持启动时方案。动作由使用者确认，跨段时间与确认动作只统计一次 |
| T43 | 使用新配置或包含旧工作、休息时长的配置打开设置 | 直接看到模块编辑器。新配置为工作 25 分钟和休息 5 分钟，旧时长出现在对应模块。引用的次数以“重复 … 次”显示 |
| T44 | 从初始配置打开设置，添加一个相邻休息模块，再读取已保存且关闭合并的计划 | 新计划默认合并相邻休息，已有计划沿用保存的开关选择。“完整计划预览”只显示模块名称、时长和动作 |
| T45 | 检查主窗口、资料卡、预警、悬浮沙漏和全屏休息窗 | 常规与加粗字重由应用内置的 Noto Sans SC 提供，出版物附原版版权和 OFL 许可证 |
| T46 | 新建空白组合并原位展开，将同一组合插入计划两次并分别设为 2 次、3 次，再嵌入另一个组合，保存后重开 | 组合标题按编号命名，只有引用可设次数。编辑模块会同步到各引用，预览和重开均按各处次数展开。旧数据中的重复次数、执行顺序及轮序保留。循环引用和删除仍被使用的定义均受限 |
| T47 | 对包含嵌套组合的计划点击「保存为组合」，再对四层计划及非法计划操作 | 原计划仍按原顺序执行。新组合随设置保存并可复用；四层计划展开后保持时长、顺序和动作；非法计划显示原因 |
| T48 | 在设置中修改、还原、保存或放弃编排与扣分参数，再尝试切页和关闭窗口 | 标志与当前修改一致，未修改时直接离开，有修改时弹出三个选项。保存失败留在设置页，恢复计时记录时不会提交失败的设置 |

附加交互检查包括按钮文案、Tab到达应急出口、200%缩放下退出按钮可用、预告不抢输入焦点，以及确认页在原全屏窗口展示、恢复后的确认使用主窗口。暂停页区分“继续本轮”和“结束本轮”。

## 4. 暂定性能与可用性门槛

这些是待测目标，不是已验证结论。M5报告必须写清Windows版本、CPU、内存、屏幕数和缩放；参考环境为Windows11、4核以上、8GB内存、SSD、Release构建、无调试器。

| 项目 | 目标与测量方法 |
| --- | --- |
| 应急退出响应 | 正常系统负载下，从输入事件到所有本应用遮罩消失，95%不超过300毫秒；至少测试30次；注入数据库失败后仍测 |
| 创建休息窗口 | 2秒内完整成功或全部回退；不能无限等 |
| 到点误差 | 机器保持唤醒、无缺口暂停时，25分钟倒计时到期偏差≤1秒；显示等待另列 |
| 后台CPU | 最小化托盘连续5分钟，进程平均CPU占整机总能力<1%；记录采样方法 |
| 内存 | 单屏空闲Private Bytes≤150MB；双屏休息≤200MB；超出先分析，不擅自删功能掩盖 |
| 重复使用 | 100次模拟阶段切换后，强制GC稳定值相对前10轮增长≤20MB，窗口/系统事件订阅不逐轮累积；另做至少8小时实际常驻检查 |
| 冷启动 | 参考环境3秒内出现可操作主窗；不含系统首次安全扫描时间，必须单列首次运行情况 |

性能不达目标时提交数据、原因和可选取舍，不能把目标删掉或把调试版本结果当最终结论。可靠退出与正确计时优先于装饰动画。

## 5. 测试与运行证据格式

每批交付在 `docs/delivery/Mx-report.md` 中包含：

1. 本批实现范围和修改文件。
2. 对应R/T编号；每项标记通过、失败、未测，附原因。
3. 实际执行的构建/测试命令、退出码、测试数量和日志路径。
4. Windows实机项目的环境信息、截图或录屏路径；假实现不能当成实机证据。
5. 数据样例：预期与实际时长、记录条数、活动状态，不包含私人文字。
6. 未完成、已知问题和下一批需要的输入。

最低运行命令由M0在README固定，通常包括 `dotnet restore`、`dotnet build -c Release`、`dotnet test -c Release`；打包命令必须明确目标项目和 `win-x64`。后续AI使用这些命令，不根据猜测填写“测试通过”。
